# 多语言（i18n）

《传奇-Next》**默认全中文化**，并允许在游戏内切换其他语言；语言选择随账号保存，
换角色、重新登录都会保留。客户端也可以在没有连服务端的情况下切换界面语言。

## 分层设计

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 编译期内置文本 | `mir-core::i18n::{Language, TextKey, text}` | 用 `(Language, TextKey)` 的穷举 `match` 保证不漏翻；默认简体中文 |
| 运行时语言包 | `config/lang/*.json` → `LanguageLibrary` | 覆盖内置文本、补充地图名等内容文本，**不用改代码** |
| 会话级设置 | `mir-core::i18n::LanguageCatalog` | 每个玩家的当前语言，默认简体中文 |
| 账号持久化 | `mir-store` 的 `accounts.language`（迁移 `0002`） | 换角色 / 重登 / 换设备都保留 |
| 客户端本地设置 | `mir-client` 的 `settings.json` | 未连服务端时也能切换界面语言 |

## 语言包格式

`config/lang/<code>.json`：

```json
{
  "language": "zh-cn",
  "server": {
    "welcome": "欢迎来到传奇-Next。",
    "language_changed": "语言已切换为简体中文。"
  },
  "maps": {
    "0": "比奇省"
  }
}
```

- `server` 的键与 `TextKey::key()` 一一对应（见下表）。
- `maps` 的键是地图文件名（不含 `.map`），值是地图标题；服务端 `MapInformation`
  的地图名就走这里，未收录时用文件名兜底。
- 启动时会加载 `config/lang/` 下的全部 `*.json`，覆盖编译期内置语言包；
  目录不存在则直接用内置语言包（所以精简部署也不会缺中文）。

## 文本键

| 键 | 简体中文 |
| --- | --- |
| `welcome` | 欢迎来到传奇-Next。 |
| `account_banned` | 该账号已被封禁。 |
| `wrong_password` | 账号或密码错误。 |
| `too_many_characters` | 角色数量已达上限。 |
| `language_changed` | 语言已切换为简体中文。 |
| `unknown_language` | 未知的语言代码，可用：zh-cn、en。 |
| `server_full` | 服务器人数已满，请稍后再试。 |
| `unsupported_command` | 不支持的命令。 |
| `character_name_taken` | 该角色名已被占用。 |
| `character_name_invalid` | 角色名不合法：3-15 个汉字、字母、数字或下划线。 |
| `login_success` | 登录成功。 |

## 语言代码

| 代码 | 语言 | 接受的别名 |
| --- | --- | --- |
| `zh-cn`（默认） | 简体中文 | `zh`、`cn`、`zh_cn`、`chs` |
| `en` | English | `en-us`、`en_us` |

别名由 `mir_core::Language::from_code` 与 `mir_store::normalize_language` 归一，
两层接受的输入完全一致（存储层会落成标准代码）。

## 游戏内切换

在聊天框输入：

```text
/language            显示当前语言
/language en         切换到 English
/language zh-cn      切换回简体中文
```

服务端行为：切换到受支持的语言 → 更新会话语言、写回 `accounts.language`、
回一条该语言的系统提示；非法代码 → 回「未知语言」提示且不改设置。

> **为什么用聊天指令而不是新包**：Crystal 的 `ClientPacketIds` / `ServerPacketIds`
> 是连续编号（0..152 / 0..278），新增「设置语言」包会与 Crystal 客户端编号表冲突，
> 破坏「现有客户端可直接连接」。等我们自己的 Rust 客户端落地后，再在**不影响
> Crystal 编号段**的区间追加扩展包，并记录到 `docs/protocol/`。

## 客户端

```bash
# 本次启动使用英文，并保存到本地设置
cargo run -p mir-client -- --lang en

# 只修改并保存语言设置
cargo run -p mir-client -- --set-language zh-cn

# 列出支持的语言
cargo run -p mir-client -- --list-languages
```

设置文件：Windows 为 `%APPDATA%\mir-next\settings.json`，其它平台为
`$HOME/.config/mir-next/settings.json`；文件缺失或损坏时回落到默认的简体中文。

## 新增文本的流程

1. 在 `TextKey` 里加一项，并在 `TextKey::key()` / `TextKey::ALL` 里登记；
2. 在 `text()` 的 `match` 里补齐**每种语言**（编译器会强制）；
3. 在 `config/lang/zh-cn.json` 与 `config/lang/en.json` 的 `server` 段加上同一个键
   （**要跑测试**：`embedded_pack_matches_builtin_text` 会拦住两边不一致）；
4. 服务端用 `library.text(language, TextKey::Xxx)` 发送，不要写死字符串。

## 6. 覆盖审计（2026-10，第 1 轮）

本轮对「服务端 TextKey / 语言包 / 客户端 Label / 运行时硬编码」做了全量核对。结论：

| 层 | 覆盖情况 | 证据 |
|---|---|---|
| 服务端 `TextKey` | **11/11 键**，简体中文与英文都由穷举 `match` 提供 | `mir-core/src/i18n.rs:88-156` |
| `config/lang/zh-cn.json` | `server` 11 键、`maps` 1 键（`"0"`） | 与 `TextKey::ALL` 完全一致 |
| `config/lang/en.json` | `server` 11 键、`maps` 1 键（`"0"`） | 与中文包键集合完全一致，无缺键/多键 |
| 客户端 `Label` | 约 190 个标签，`Label::text` 是**无通配符**的穷举 `match`，每个变体都有中英两份 | `crates/mir-client/src/ui/labels.rs` |
| 客户端市场标签 | 39 个（市场/寄售/拍卖/出价/翻页/失败原因/上架结果等） | `labels.rs` 的 `Market…ConsignSelected` |
| 运行时活动文案 | **未覆盖**：服务端多个模块仍直接写中文 | 见下表 |

### 6.1 客户端 `Label` 的审计口径

客户端文案**不在** `config/lang/*.json` 里，而是编译期内置在
`crates/mir-client/src/ui/labels.rs` 的 `Label` 枚举：

```rust
pub const fn text(self, language: Language) -> &'static str {
    match (self, language) { /* 无 `_ =>` 通配符 */ }
}
```

因此只要 `cargo check -p mir-client` 通过，就说明**每个** `Label` 在
`Language::ZhCn` / `Language::En` 下都有文案；测试
`new_ui_labels_have_both_languages`（`labels.rs` 末尾）再对其中 **126 个**关键标签做
运行时断言（非空、且中英不相同），其余 64 个由穷举 `match` 在编译期保证。市场相关的
39 个标签已包含在这份列表里。

> **不要把客户端 Label 写进 `config/lang/`**：语言包只反序列化 `server: BTreeMap` 与
> `maps: BTreeMap`，多出来的键会被忽略；而且 `Label` 是编译期枚举，改语言包不会生效。
> 要新增客户端文案，改 `labels.rs` 并同时补 `Label::ALL` 风格的测试。

### 6.2 服务端仍硬编码中文的位置（下一轮 i18n 收口）

| 文件 | 位置 | 内容 |
|---|---|---|
| `crates/mir-server/src/market.rs` | `:161-190` | 卖家标签（已售出/已过期/出售中/已有出价/无人出价） |
| `crates/mir-server/src/market.rs` | `:563`、`:568`、`:965`、`:969`、`:987`、`:1010`、`:1014`、`:1083`、`:1091`、`:1365`、`:1389` | 成交/出价/退款/过期退回的 `MarketSuccess` 与系统邮件正文 |
| `crates/mir-server/src/trade.rs` | `:321-424`、`:467-477`、`:711`、`:756` | 交易拒绝、邀请、等待确认、交易成功 |
| `crates/mir-server/src/group.rs` | `:484-668`、`:843-858` | 组队邀请/接受/踢人提示 |
| `crates/mir-server/src/items.rs` | `:1767-1991` | 使用物品/药水/等级限制提示 |
| `crates/mir-server/src/mail.rs` | `:336-340`、`:526` | 邮件错误与新邮件提示 |
| 其它 | `guild.rs`、`npc.rs`、`quests.rs`、`conquest.rs`、`world.rs`、`guild_buffs.rs`、`magic.rs` | 行会/商店/任务/攻城等系统聊天 |

审计命令（PowerShell，只读）：

```powershell
# 列出所有直接写中文的系统聊天/邮件/提示（粗略但可复跑）
Get-ChildItem crates/mir-server/src -Filter *.rs |
  Select-String -Pattern 'send_system_chat\([^,]+, "[^"]*[\u4e00-\u9fa5]|format!\("[^"]*[\u4e00-\u9fa5]' |
  Select-Object Path, LineNumber, Line
```

结论：**服务端 TextKey 与两份语言包是完整的；缺口在于「运行期直接拼中文」**。
粗略统计全仓约 **94 处**玩家可见硬编码中文：`market.rs` 19 处（7 个卖家标签 + 12 条成交/退款/
过期消息）、`trade.rs` 16 处，其余 59 处分布在 `group.rs`（23）、`items.rs`（13）、`npc.rs`（9）、
`conquest.rs`（4）、`mail.rs`（3）、`guild.rs`/`quests.rs`（各 2）、`guild_buffs.rs`/`magic.rs`/
`world.rs`（各 1）。
这些文案不会随 `/language` 切换，属于 `AGENTS.md` 的约定偏差，本轮只登记、不改代码；
下一轮按「新增文本的流程」逐条迁到 `TextKey`。

两个下一轮必须一起解决的 API 限制：

* **`TextKey` 目前无参数**，`text()` 返回 `&'static str`（`mir-core/src/i18n.rs:63-156`）。
  市场消息需要 `item_name`/`gold` 等参数，直接加键只能存模板、无法格式化。收口时需要
  增加参数化入口（如 `format_text(language, key, args)` 或每键专用函数），并让语言包里的
  `{}`/`{0}` 占位符真正生效，否则 `config/lang` 的覆盖会失效。
* **`MarketFailReason` 是 0..=10**（9 = 出价太低、10 = 拍卖已结束），客户端按
  `GameScene.cs:5669-5708` 的编号本地化；不要按 0..=8 处理（0..=8 是 `ServerPackets.cs:4322-4332`
  的旧注释范围）。本作 `market.rs` 的 `MarketFailReason::reason()` 与客户端 `Label::MarketFail*`
  已按 0..=10 对齐。
