# 多语言（i18n）

《传奇-Next》默认**全中文化**，并允许在游戏内切换其他语言。

## 设计

| 层面 | 做法 |
| --- | --- |
| 服务端文本 | `mir-core::i18n`：`Language` + `TextKey` + `text(language, key)`，默认 `Language::ZhCn` |
| 缺少翻译 | 编译期挡住：`text` 是 `(Language, TextKey)` 的穷举 `match`，新增键必须补齐所有语言 |
| 每个玩家的语言 | `LanguageCatalog`，会话级状态，默认简体中文 |
| 游戏内切换 | 聊天指令 `/language <代码>`（如 `/language en`、`/language zh-cn`） |
| 客户端界面 | 本地设置项（里程碑 M6 实现渲染时接入，默认跟随服务端欢迎语的语言） |

## 为什么不用协议包

Crystal 的 `ClientPacketIds` / `ServerPacketIds` 是连续编号（0..152 / 0..278），
新增一个「设置语言」包会与 Crystal 客户端的编号表冲突，破坏「现有客户端可直接连接」
这一目标。因此当前用聊天指令实现切换；等我们自己的 Rust 客户端落地后，
再在**不影响 Crystal 编号段**的区间追加扩展包（并在 `docs/protocol/` 记录差异）。

## 语言代码

| 代码 | 语言 |
| --- | --- |
| `zh-cn`（默认，也接受 `zh` / `cn` / `chs`） | 简体中文 |
| `en`（也接受 `en-us`） | English |

## 新增文本的流程

1. 在 `TextKey` 里加一项；
2. 在 `text()` 的 `match` 里补齐**每种语言**（编译器会强制）；
3. 在 `i18n.rs` 的测试 `every_key_is_translated_in_every_language` 里加上新键；
4. 服务端用 `session.language.text(TextKey::Xxx)` 发送，不要写死字符串。
