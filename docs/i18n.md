# 多语言（i18n）

《传奇-Next》**默认全中文化**，并允许在游戏内切换其他语言；语言选择随账号保存，
换角色、重新登录都会保留。客户端也可以在没有连服务端的情况下切换界面语言。

> **默认数据集 = `cjlaaa`（简体中文库，v105）**；`Jev` 仅作英文兜底与数据契约测试。
> 数据文本（物品/怪物/地图/任务/NPC）的语言覆盖与切换风险见
> [`world/data-languages.md`](world/data-languages.md)。

## 分层设计

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 编译期内置文本 | `mir-core::i18n::{Language, TextKey, text}` | 用 `(Language, TextKey)` 的穷举 `match` 保证不漏翻；默认简体中文 |
| 运行时语言包 | `config/lang/*.json` → `LanguageLibrary` | 覆盖内置文本、补充地图名等内容文本，**不用改代码** |
| 会话级设置 | `mir-core::i18n::LanguageCatalog` | 每个玩家的当前语言，默认简体中文 |
| 账号持久化 | `mir-store` 的 `accounts.language`（迁移 `0002`） | 换角色 / 重登 / 换设备都保留 |
| 客户端本地设置 | `mir-client` 的 `settings.json` | 未连服务端时也能切换界面语言 |

## 语言包格式

`config/lang/<code>.json`：

```json
{
  "language": "zh-cn",
  "server": {
    "welcome": "欢迎来到传奇-Next。",
    "language_changed": "语言已切换为简体中文。"
  },
  "maps": {
    "0": "比奇省",
    "0104": "书店",
    "0157": "祖玛寺庙入口"
  }
}
```

- `server` 的键与 `TextKey::key()` 一一对应（见下表）。
- `maps` 的键是地图文件名（不含 `.map`），值是地图标题；当前 **25 个键**（常用图），
  客户端 HUD/小地图/大地图/传送点/组队面板走这里，未收录时回退服务端标题 → 文件名
  （详见 `docs/client.md` §5.25）。
- 启动时会加载 `config/lang/` 下的全部 `*.json`，覆盖编译期内置语言包；
  目录不存在则直接用内置语言包（所以精简部署也不会缺中文）。

## 文本键

| 键 | 简体中文 |
| --- | --- |
| `welcome` | 欢迎来到传奇-Next。 |
| `account_banned` | 该账号已被封禁。 |
| `wrong_password` | 账号或密码错误。 |
| `too_many_characters` | 角色数量已达上限。 |
| `language_changed` | 语言已切换为简体中文。 |
| `unknown_language` | 未知的语言代码，可用：zh-cn、en。 |
| `server_full` | 服务器人数已满，请稍后再试。 |
| `unsupported_command` | 不支持的命令。 |
| `character_name_taken` | 该角色名已被占用。 |
| `character_name_invalid` | 角色名不合法：3-15 个汉字、字母、数字或下划线。 |
| `login_success` | 登录成功。 |

## 语言代码

| 代码 | 语言 | 接受的别名 |
| --- | --- | --- |
| `zh-cn`（默认） | 简体中文 | `zh`、`cn`、`zh_cn`、`chs` |
| `en` | English | `en-us`、`en_us` |

别名由 `mir_core::Language::from_code` 与 `mir_store::normalize_language` 归一，
两层接受的输入完全一致（存储层会落成标准代码）。

## 游戏内切换

在聊天框输入：

```text
/language            显示当前语言
/language en         切换到 English
/language zh-cn      切换回简体中文
```

服务端行为：切换到受支持的语言 → 更新会话语言、写回 `accounts.language`、
回一条该语言的系统提示；非法代码 → 回「未知语言」提示且不改设置。

> **为什么用聊天指令而不是新包**：Crystal 的 `ClientPacketIds` / `ServerPacketIds`
> 是连续编号（0..152 / 0..278），新增「设置语言」包会与 Crystal 客户端编号表冲突，
> 破坏「现有客户端可直接连接」。等我们自己的 Rust 客户端落地后，再在**不影响
> Crystal 编号段**的区间追加扩展包，并记录到 `docs/protocol/`。

## 客户端

```bash
# 本次启动使用英文，并保存到本地设置
cargo run -p mir-client -- --lang en

# 只修改并保存语言设置
cargo run -p mir-client -- --set-language zh-cn

# 列出支持的语言
cargo run -p mir-client -- --list-languages
```

设置文件：Windows 为 `%APPDATA%\mir-next\settings.json`，其它平台为
`$HOME/.config/mir-next/settings.json`；文件缺失或损坏时回落到默认的简体中文。

## 新增文本的流程

1. 在 `TextKey` 里加一项，并在 `TextKey::key()` / `TextKey::ALL` 里登记；
2. 在 `text()` 的 `match` 里补齐**每种语言**（编译器会强制）；
3. 在 `config/lang/zh-cn.json` 与 `config/lang/en.json` 的 `server` 段加上同一个键
   （**要跑测试**：`embedded_pack_matches_builtin_text` 会拦住两边不一致）；
4. 服务端用 `library.text(language, TextKey::Xxx)` 发送，不要写死字符串。

### 并发约定（第 16 轮事故后新增，务必遵守）

`crates/mir-core/src/i18n.rs`、`config/lang/*.json`、`tools/i18n/verify_text_keys.py`、
本文件 **四者是多人热点**，同一时段**只允许一个 owner 写**：

- 默认 owner：**礼部**（负责文档表格与白名单同步）；
- 需要新增 TextKey 的其他人：在任务回执里写明 **键名 / 中文 / 英文 / 参数**，
  由 owner 统一落地，或提前向队长报时段，**不要自行手改**；
- 一旦发现自己的改动被覆盖：**立刻停止手改**、在回执里报告，不要继续叠加；
- 修改这几个文件时用 `read` / `edit` 工具或 `File.ReadAllText/WriteAllText`
  （**不要用 `Get-Content -Raw` + `Set-Content`**：Windows PowerShell 5.1 按 ANSI 读 UTF-8，
  会把中文写坏、并丢掉换行）。

### 6.1 客户端 `Label` 的审计口径

客户端文案**不在** `config/lang/*.json` 里，而是编译期内置在
`crates/mir-client/src/ui/labels.rs` 的 `Label` 枚举：

```rust
pub const fn text(self, language: Language) -> &'static str {
    match (self, language) { /* 无 `_ =>` 通配符 */ }
}
```

因此只要 `cargo check -p mir-client` 通过，就说明**每个** `Label` 在
`Language::ZhCn` / `Language::En` 下都有文案；测试
`new_ui_labels_have_both_languages`（`labels.rs` 末尾）对其中 **173 个**关键标签做
运行时断言（非空、且中英不相同）；另有 `Label::ALL`（327 项）与
`every_label_has_both_languages` 遍历**全部** 327 个变体，配合无通配符的穷举 `match`，
中英双语由测试 + 编译期双重保证。
市场/商城页签相关的标签已包含在这份列表里。

**客户端残余（第 3 轮更新）**：窗口标题（`WindowTitleMap/Login/Live`）、设置面板的快捷键
说明（键名 ASCII，如 `Shift + WASD`，动作文案走 `Label::Key*`）都已收进 `Label`。
现在 `Label` 之外只剩**控制台/诊断文本**：

* 命令行 `--help` 与参数错误提示、`main.rs` 的启动 `println!`（终端可见，不是游戏 UI）；
* `NetStatus::label()`（叠层/日志状态名）仍是中文；
* `classify_login_error` 用中文关键字匹配内部错误串（只做分类，不直接显示给玩家）。

这些不影响游戏内界面语言切换（面板/窗口标题/快捷键说明都走 `Label`/`TextKey`），
属于下一轮「控制台 i18n」的收口范围。

> **不要把客户端 Label 写进 `config/lang/`**：语言包只反序列化 `server: BTreeMap` 与
> `maps: BTreeMap`，多出来的键会被忽略；而且 `Label` 是编译期枚举，改语言包不会生效。
> 要新增客户端文案，改 `labels.rs` 并同时补 `Label::ALL` 风格的测试。

### 7.5 参数化 TextKey 的 API（第 3 轮已落地）

现状（第 3 轮已落地）：`mir_core::i18n::format_text(language, key, &[("name", value)])`、
`TextKey::args()`（每个键声明的参数名）、`LanguageLibrary::format(language, key, args)`、
`mir_core::i18n::text(language, key)`（无参键）都已可用；行会权限兜底还有
`guild_permission_name(language, "CanRecruit")`。`World::text/format` 是它们按玩家语言的封装。
下面保留实现约定，作为新增键/新增调用点的规范（三步均已按此实现）：

**① 模板与参数**

```rust
// mir-core/src/i18n.rs
impl TextKey {
    /// 该键的模板参数名（用于语言包校验与文档生成）。
    pub const fn args(self) -> &'static [&'static str] { … }
}

/// 用命名占位符渲染：`{name}`、`{gold}`；未知占位符原样保留。
pub fn format_text(language: Language, key: TextKey, args: &[(&str, &str)]) -> String;

impl LanguageLibrary {
    /// 优先语言包里的覆盖模板，缺失时回落内置模板（与 `text()` 同口径）。
    pub fn format(&self, language: Language, key: TextKey, args: &[(&str, &str)]) -> String;
}
```

* 占位符统一 `{snake_case}`；模板里 `{{` / `}}` 转义为字面大括号；
* `args` 里没给的占位符**保留原样**（不 panic），便于渐进迁移；
* 新增测试：`every_key_has_same_placeholders_in_every_language`（中文模板与英文模板的
  占位符集合必须相等）、`format_leaves_unknown_placeholders`。

**② 服务端拿得到「玩家语言」（第 3 轮已落地）**

`LanguageCatalog` 在 `Session` 里（`session.rs`），而 `send_system_chat` 的绝大多数调用点
在 `World`（`market.rs`/`trade.rs`/`group.rs`/…）。第 3 轮的实现（不给 `Player` 加字段，
避免波及大量测试字面量）：

1. `World` 持有 `Option<Arc<LanguageLibrary>>`（`set_languages`，`server.rs` 构建后注入；
   不注入时用 `mir_core::i18n::text/format_text` 的内置模板，行为一致）；
2. `World.player_languages: HashMap<u32, Language>` 旁置映射：登录与 `/language` 切换时
   由 `session.rs` 调 `set_player_language`，缺省 `Language::ZhCn`；
3. `World` 的统一出口（`world.rs`）：

```rust
impl World {
    pub fn set_languages(&mut self, languages: Arc<LanguageLibrary>);
    pub fn set_player_language(&mut self, object_id: u32, language: Language);
    pub fn player_language(&self, object_id: u32) -> Language;
    pub fn text(&self, object_id: u32, key: TextKey) -> String;
    pub fn format(&self, object_id: u32, key: TextKey, args: &[(&str, &str)]) -> String;
    pub fn broadcast_text(&mut self, map: &str, key: TextKey, args: &[(&str, &str)]);
}
```

4. 邮件正文/`S.MarketSuccess` 在**发送时**按收件人语言渲染并落库；**离线收件人回落
