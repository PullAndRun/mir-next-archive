# Gate 与验收脚本的教训（2026-10-21/22，DR-1/PS-1/EQ-1/卖肉链 实战）

> 这些教训都来自**同一个下午**：DR-1 的"客户端收不到 `S.Revived`"被查了 5 轮，最后发现是
> **脚本自己把"时长"当成"绝对时间"**；新手链的两次失败则来自**验收假设与参考数据不符**。

## 1. 先自检脚本的时间语义，再怀疑产品

**案例**：`next_packet(deadline)` 形参是**绝对时间**，调用点传的是**时长**（`1.0` 而不是 `time.time()+1.0`）。
后果：读包窗口瞬间过期 → 服务端 10ms 内就发出的 `S.Revived(136)` 被判定"1s 内未收到"，
连续 4 次假阴性，把"产品正常"误报成"产品 BLOCKED"，并浪费了一轮排查（查 writer、查 sender、查死标记）。

**规则**：
- 所有 `wait_for/next_packet/poll` 类函数，**函数名带 `_until`/`_deadline` 的必须传绝对时间**；
- 脚本里新增等待时，用 `time.time() + N` 一次性算好，禁止在循环里反复传常量；
- gate 报红时，**先打印"实际等待了多少毫秒"**，再怀疑产品。

## 2. 验证新功能前必须重建二进制

**案例**：DR-1 gate 前 3 次失败，第一嫌疑是"服务端二进制还是旧的（不含 `C.TownRevive` 分派）"。
虽然这次证明不是旧二进制，但这条嫌疑**必须优先排除**，否则可能白查很久。

**规则**：跑任何端到端 gate 前，先 `cargo build --release -p <crate>`，并在日志头记录**二进制 mtime + git HEAD**。

## 3. 客户端缓存坐标 ≠ 服务端权威坐标

**案例**：gate 用 `S.ObjectMonster/S.ObjectWalk` 缓存位置判断"与怪相邻（d=1）"，
但服务端实际距离 >10（怪在追、id 在换），导致"站定挨打 180s 零伤害"。

**规则**：
- 判定接敌/相邻用**因果证据**（`S.DamageIndicator` 命中目标 / `S.ObjectStruck` 打到自己）；
- 位置只用于"大致靠近"，不用于"精确判定"；
- `stale_ms` 要区分"位置两次相同"与"很久没更新"，后者不能当站定。

## 4. 验收假设必须能被参考数据支持

**案例**：新手链最初假设"1 级清洁角色能接 quest 7（见战士教官）"，
实测 `MinLevel=4`；改假设"quest 3 是 1 级纯对话"，实测 `required_quest=2`（需要先完成 quest 2）。
两次都白跑，最后发现**唯一 1 级无前置的是 quest 1（收集 5 片食人花叶子）**。

**规则**：写 gate 前先 dump 数据（等级/前置/奖励），把"假设"变成"数据事实"，再写脚本。

## 5. 并发编译会让测试假红

**案例**：`duo_smoke` 在并发编译时 212s 超时（组队经验用例 FAIL），空载 149s 全绿。
根因是测试等待预算对负载敏感。

**规则**：
- 编译/测试/起服务端前确认机器空闲（`Get-Process cargo,rustc,mir-server`）；
- 需要等待"游戏事件"的用例改成**事件驱动**（收到包即返回），不要用固定轮数；
- 失败时必须打印诊断（攻击次数/刷怪次数/收到的包种类），让下次红能直接定位。

## 6. 结构性缺口不要用 gate 补

**案例**：PS-1 需要"可辨识状态"，最初设计成"卖物得金币"，但 NPC 走不到 → gate 卡住。
改成"背包/装备的 `unique_id` + 耐久逐项比对"后立刻通过——`unique_id` 是服务器分配的，比金币更难伪造。

**规则**：gate 卡在"取证手段"时，换一个**更硬、更好取**的判据，不要为了让旧判据成立去改产品。

## 7. `@item <name>` 可能给到高等级模板

**案例**：`duo_smoke` 经验用例先用 `@item sword` 给 A 武器，结果匹配到 `SpiritBlade`（req_level=20）；A 只有 10 级，`C.EquipItem` 返回 `MoveItem{success:false}`。测试没等装备回执，直接进入战斗 → 72 次攻击 0 击杀，误判为“怪不反击”。

**规则**：
- 测试给装备必须用**低等级模板名**（如 `wooden`/`dagger`），并等待 `S.EquipItem{success:true}`；
- 装备失败时立即失败并打印原因，不要进入战斗循环；
- 战斗用例失败时先看“第一刀是否真的造成伤害”，再怀疑 AI/命中。

## 8. 实时战斗不适合做门禁断言

**案例**：`duo_smoke` 两个组队经验用例依赖 `@mob` 刷怪 + 实时攻击；怪会移动、命中随机，CI 上 72 刀 0 击杀，连续红。  
**处理**：
- 逻辑覆盖下沉到 `tests/group.rs::group_exp_shares_is_deterministic_in_range_out_of_range_dead_and_off_map`（直接断言 `World::group_exp_shares`）；
- 两个 TCP 战斗用例标 `#[ignore = "flaky: ..."]`，保留代码，只让其它 5 个无战斗用例进门禁；
- TCP 层只验证包序/契约，不用实时战斗结果当断言。

**规则**：门禁断言优先“世界层纯函数/确定性包序”；命中随机与怪物移动不应成为必过条件。

## 9. 选攻击目标必须排除“训练假人/不可击杀对象”

**案例**：EQ-1 的 `--eq1` 打怪攒金币阶段选中了出生点附近的训练假人
（`target_hp=999999`、`AC=999`、`target_agility=255`）；90 秒攻击全是
`S.DamageIndicator dmg=0`，没有 `S.ObjectDied`/`S.ObjectGold`，一度被误判为
“金币掉落链路坏了”。

**规则**：
- 选目标前排除不可击杀对象（`target_hp` 极大、AC 极高、AI 为 Trainer/Tree 等）；
- 只对“真怪”断言击杀/掉落/经验；`dmg=0` 不得计入进度；
- 先打印目标 hp 变化/伤害数字，再断言掉落，避免把“打不动”误判成“没掉落”。

## 10. 不要用 Jev 数据判默认数据集

**案例**：默认数据集已切 `cjlaaa`，`鸡.txt` 的掉肉是 `1/5 + 1/15`（单只约 **26.7%**），
而 Jev 是 `1/1 Chicken`。gate 沿用 Jev 的“打一只必掉”假设，杀了 5 只没掉肉就报
“掉落链路坏了”，实际只是概率没到。

**规则**：
- 写 gate 前先确认当前默认库（`DB_CANDIDATES[0] = cjlaaa`）与对应掉落文件；
- 按当前数据集的概率设**击杀上限/重试预算**（26.7% 时至少给 10~20 只的预算），
  不要用另一套库的概率；
- 失败时打印“击杀数 + 掉落包/地面物品数”，区分“没掉”与“没杀到”。

## 11. NPC 页面 key 因数据而异，必须解析按钮

**案例**：cjlaaa 的 Butcher 主页面只有 `<卖/@Sell>`，**没有** `@BuySell`；
gate 若硬编码 `@BuySell`，服务端会回 `NotShopPage`/`NotACurrentButton`。
卖肉链最终改为 `@main` → 解析页面按钮 → 按实际 key 进入 `[@Sell]` 后成功。

**规则**：
- gate 打开 NPC 一律先发 `@main`，从 `S.NPCResponse` 原文解析 `<文本/@key>`；
- 只点当前页真实存在的按钮，不按“常见页名”硬编码；
- 找不到预期按钮时打印完整页面原文 + 当前页 key，便于判断是数据差异还是包丢失。

## 12. 新手出生装只在背包，先 `C.EquipItem` 再战斗

**案例**：新手出生装（Crystal `HumanObject.cs:234-246` 同语义）只放在**背包**里，
gate 没穿就开打。1 级裸装 `min_dc/max_dc=0`，`armour >= damage` 时伤害为 0，
战斗日志全是 `Miss(0)`，被误判成“命中/伤害坏了”。

**规则**：
- 战斗前必须发 `C.EquipItem`，等 `S.EquipItem{success:true}`，并断言装备槽/属性已变；
- 1 级基础 `accuracy=5`（不是 7）；出生武器 **+2 accuracy 是本作扩展**，
  直接拿 DB 模板算会得到 54.5% 命中——gate 的期望值要按实际装备后的属性算；
- 先打印 `min_dc/max_dc/accuracy` 与首刀伤害，再断言击杀。
